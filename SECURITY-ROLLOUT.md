# Production security rollout

This branch changes the AI assistant to require a Supabase login and a Cloudflare per-user rate limiter. The Worker intentionally fails closed until all bindings and secrets are configured. Do not merge before deploying the new Worker and testing with a real account; the old live Worker remains vulnerable until deployment.

1. Review all existing `public.profiles` RLS policies and database triggers in Supabase. Remove any policy that lets a browser read other profiles or write paid entitlements. Back up the table; inspect current `plan` values for self-assigned Pro/Firm records. Apply `supabase/migrations/20260924_lock_profiles.sql`. Verify as two different users that each can read only their own profile and cannot insert or update `plan`, `subscription_status`, `admin`, `role` (if role conveys privilege), or any other entitlement column. If `role` conveys privilege, remove it from the INSERT/UPDATE grants too.
2. Configure Worker secrets `ANTHROPIC_API_KEY`, `SUPABASE_URL`, and `SUPABASE_PUBLISHABLE_KEY` through Cloudflare; set the last two to the existing Supabase URL and publishable key. Deploy `wrangler.toml` with its `AI_RATE_LIMITER` binding. Confirm unauthenticated calls get 401, unapproved origins get 403, oversized bodies get 413, and signed-in calls hit 429 at the configured limit. Add Cloudflare account-level WAF/budget alerts and an appropriate monthly Anthropic spend cap. The per-minute limit is abuse protection, not a billing quota.
3. Dodo's existing `server/app/main.py` handles PDF converter licenses, not website Pro/Firm subscriptions. No website paid entitlement webhook exists here. Do not grant Pro/Firm access based on `signup.html` or old metadata. Build and test a separate Dodo verified webhook mapped to Supabase user IDs and service-role-only entitlement writes before enabling paid website features. Review existing Pro/Firm rows manually before trusting them.
4. Review Git history with a credential scanner in your own trusted environment and rotate any credential ever committed. This change removes `.wrangler/cache/wrangler-account.json` from the current tree; prior public history still contains it. Rotate any credential if that file or history contained one.
5. Verify the current hosting provider and DNS before changing visibility. Deploy to a host that supports private GitHub source, test the preview and production domain, then make the repository private. On GitHub Free, making a GitHub Pages source repository private may unpublish the site. Browser-delivered HTML and JS remain visible regardless of repository visibility.
